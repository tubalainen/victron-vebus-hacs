# Victron VE.Bus (MK3) 1.1.4

Setting changes in RAM now work on MultiPlus-II devices that report the stored value.

## Fixed

- **"Setting N reads back … after writing …"** on a MultiPlus-II (firmware 556). The
  Multi did apply the change (the charger followed a lower charge current limit), but
  it reports the stored (EEPROM) value when the setting is read. The integration now
  accepts a RAM-only change that the Multi acknowledges, and the number no longer
  jumps back to the stored value.
- **Save settings permanently** stores the value in effect on these devices, instead
  of the stored value it read back.

## Changed

- The setting numbers (charge current limit, configured AC input current limits,
  absorption, float and solar & wind priority voltage) have a **Stored value**
  attribute while a different RAM value is in effect. It is the value the Multi
  returns to after a restart.
- The diagnostics download contains `ram_values` and `stored_raw`.

## After updating

Changes that failed with 1.1.3 or earlier weren't remembered: set them again. Use
*Save settings permanently* if they should survive a restart.
