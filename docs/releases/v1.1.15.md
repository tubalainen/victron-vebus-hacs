# Victron VE.Bus (MK3) 1.1.15

Fixes *Reconfigure* for a new path to the same MK3. Nothing in this release writes to
the Multi or restarts it.

## Fixed

- **Reconfigure refused the same MK3 under another path.** Changing `/dev/ttyUSB0` to
  `/dev/serial/by-id/usb-VictronEnergy_MK3-USB_Interface_…` ended with "This is a
  different MK3 interface than the one configured". In Docker, a by-id path mapped in
  `devices:` is a device node of its own, not a link, so Home Assistant can't read the
  USB serial number behind it; the integration then compared the path itself with the
  serial number. Now:
  - A serial number that can't be read is no longer taken for another interface. A
    by-id name that contains the configured serial number counts as the same MK3;
    otherwise the new path is checked by talking to the MK3 and the Multi.
  - A known serial number that differs is still refused.
  - A path that doesn't exist in Home Assistant (in Docker: not mapped into the
    container) is reported as such, in *Reconfigure* and when adding the integration.
  - A new name for the port already in use isn't opened a second time to check it.
    The device numbers decide, so `/dev/ttyUSB0` and a Docker by-id node of the same
    MK3 count as the same port.
