# Victron VE.Bus (MK3) 1.0.0

The first stable release of this Home Assistant integration for Victron VE.Bus
inverter/chargers (MultiPlus, MultiPlus-II, Quattro, ...) through a Victron MK3-USB
interface. It is a ground-up rewrite inspired by
[j9brown/victron-mk3-hass](https://github.com/j9brown/victron-mk3-hass), with a bundled
protocol driver: no extra Python package and no internet access needed at install.

> [!CAUTION]
> Use at your own risk. This is an unofficial community project, not made, endorsed or
> supported by Victron Energy, and provided "as is" without any warranty. The authors
> and contributors take no responsibility whatsoever for any damage. Controlling an
> inverter/charger can cut the power to your loads and can damage batteries. If you are
> not sure what a setting does, do not change it.

## Highlights

- **Monitoring:** AC input and output per phase, battery, charger and inverter,
  state of charge, device and charge state, mode and front switch, alarms, the eight
  front panel LEDs (off / on / blinking), relay, virtual switch and charger settings.
- **Energy dashboard:** grid import and export, AC output and battery charged /
  discharged energy, for the system and for every unit.
- **Alarm notifications:** an Alarm event entity and repair issues for overload, low
  battery and temperature alarms.
- **Monitor only, or monitor and control:** chosen when the integration is added, or
  with *Reconfigure*. Control has to be confirmed with a clear warning.
- **Safe controls:** routine settings on the dashboard (current limits, charge current,
  force absorption / float, solar & wind priority, ESS setpoint); everything that can
  cut the power on the AC outputs, restart the Multi or write the EEPROM only through
  *Configure → Device actions*, each with an "Are you sure?" risk dialog.
- **Multi-unit systems:** parallel, split-phase and three-phase, with a device per unit.
- **Quattro and Compact** devices, the **ESS** assistant (external control) and
  **battery operational limits** for BMS-like setups.
- **Robust connection:** automatic reconnect, resynchronisation after corrupted frames,
  values kept through a missed reply, link quality sensors and a repair issue when the
  connection is poor.

## Verified on hardware

Monitoring and mode changes are in daily use on a MultiPlus-II with an MK3-USB. Some
protocol details, among them the ESS setpoint, battery operational limits, restart,
permanent (EEPROM) writes and multi-unit systems, have only been tested against the
protocol simulator so far. They are listed in
[docs/ANALYSIS.md §5](https://github.com/tubalainen/victron-vebus-hacs/blob/main/docs/ANALYSIS.md#5-things-to-verify-on-real-hardware).
Please report your results.

## Upgrading from a 0.x beta

Nothing to do: entities of earlier versions that no longer exist are removed
automatically. If you used the `victron_vebus.set_remote_panel_state` action, it needs
`config_entry_id` and `acknowledge_risk: true` (since 0.5).
