# Victron VE.Bus (MK3) 1.1.12

Robustness release, the second part of the architecture review. Nothing changes in
how you use the integration; some actions are refused where they used to go through
with a value that couldn't be checked. Nothing in this release restarts the Multi.

## Changed

- **Values that can't be read become unknown.** Settings (charge voltages, current
  limits, battery capacity, solar & wind priority voltage), the ESS values and the slow
  RAM values are read in turns. Until now a failed read kept the last value for good;
  now it is shown as unknown after three failed reads in a row, like the fast values.
- **Charge voltages are only changed when they can be checked.** The float voltage and
  the solar & wind priority voltage need a known absorption voltage, and the
  absorption voltage a known float voltage. While the other one is unknown the change
  is refused, instead of being written unchecked.
- **The remote AC input current limit must lie within the Multi's range** (the minimum
  and maximum it reports) in the `set_remote_panel_state` action and when grid charging
  resumes. 0 A (Stop grid charging) is still allowed. The guided action shows the
  error in the form.
- Devices without info frames (Phoenix/Compact): AC input voltage and current, inverter
  current and battery current that could not be read show as unknown instead of 0.

## Fixed

- **Late replies.** When a request timed out, its reply could still arrive and be taken
  for the reply to a later request with the same tag. A tag is now not used again for
  2 seconds after a time-out, and a late reply is dropped (diagnostics:
  `late_replies`).
- **ESS writes** are read back. WriteRAMVar has no reply; if it was lost, the value
  went to the previous target unnoticed. The ESS flags are no longer written when they
  couldn't be read (writing from 0 would clear the other flag).
- **Before a value goes to the EEPROM** it is read twice and must be the same both
  times, and it must lie within the range the Multi reports. Otherwise nothing is
  written. The last 20 permanent writes, failed ones included, are in the diagnostics
  (`eeprom_writes`).
- The background retry for setting ranges tries each setting once per round, so it
  pauses polling only briefly.
- The action selectors accept up to 200 (A or V); the Multi's own range decides.

## Tests

- The simulator now behaves like a MultiPlus-II with firmware 556 by default: a
  setting read returns the stored (EEPROM) value. It can also send late replies, lose
  WriteRAMVar requests and return a corrupted read.
