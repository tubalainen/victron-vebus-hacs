# Victron VE.Bus (MK3) 1.1.14

Ripple and VE.Bus errors are now alarms, like overload, low battery and temperature.
Nothing in this release writes to the Multi or restarts it.

## Added

- **Ripple alarm:** a ripple warning or alarm fires the *Alarm* event
  (`ripple_warning`, `ripple_alarm`, `ripple_cleared`). An alarm also raises a repair
  issue that explains what to check (battery cables, connections, battery size).
- **VE.Bus error:** an error code other than 0 fires `vebus_error_alarm`, with the
  code as `error_code`, and raises a repair issue that names the code.
  `vebus_error_cleared` follows when it is gone. A different code while one is active
  is reported again.
- Both follow *Show alarms as repair issues* in the integration settings.

The two alarms come from the bytes of the MK3's `L` reply that 1.1.13 started to read.
Victron doesn't document them; the integration decodes them as VictronConnect does.
On a MultiPlus-II with firmware 556 both have been 0 (no ripple, no error) so far. A
real alarm hasn't been seen yet.

## Also

- The battery temperature (1.1.13) is verified on a MultiPlus-II with firmware 556:
  21.5 °C, the same as VictronConnect. The Multi reports the value in half kelvin.
