# Victron VE.Bus (MK3) 1.1.11

Safety release. It follows an architecture review of the integration against
Victron's documentation and other implementations. Some controls change behaviour;
read **Changed** before updating.

## Changed

- **ESS external control is experimental and off by default.** It now has its own
  option in the integration settings (*Enable ESS external control*), with a warning
  to confirm. Control always starts off after a restart of Home Assistant and is
  handed back to the Multi (0 W) when Home Assistant stops. **If you used ESS control,
  turn the option on again.**
- **Battery operational limits are marked experimental.** Turning them on asks you to
  confirm the risks.
- **The UPS function switch is disabled by default** (enable the entity to use it).
  Victron's protocol says flag 7 must be the inverse of the UPS bit, which the
  integration doesn't change; this isn't verified on hardware.
- **More controls need "Allow critical changes":** the charge current limit, the
  configured AC input current limit(s), a remote AC input limit of 0 A (passthru) and
  the battery limits.

## Fixed

- **Battery limits** are sent first and on their own: a failing ESS write no longer
  stops them (the Multi stops charging and inverting 5 minutes after the last limits).
  A critical repair issue appears when they haven't been sent for 2 minutes.
- **Battery limit voltages** must lie within the range of the absorption voltage
  setting, so a typo can't ask for 60 V on a 24 V battery.
- **Reconfigure to "Monitor only"** warned nothing while it switched battery limits
  off; it now asks for confirmation, like the integration settings.
- **Mode changes and the remote limit** kept the mode *in effect* (which includes the
  Multi's front switch) as the remote mode. With the front switch on charger only, the
  remote could be locked to charger only, with no inverter backup on a grid failure.
  They now keep the mode requested through the remote panel.
- **Stop grid charging** follows what the MK3 reports and turns off when the Multi
  restarts, so a later mode change can't silently go back to 0 A. Leaving it no longer
  falls back to a fixed 16 A (which could be above the breaker); if no limit is known,
  you give one.
- **Save settings permanently** after a reconnection could store the old value and
  report it as saved; changes from before a new connection are now forgotten.
- **Unknown LEDs** (the MK3 reports 0x1F) no longer clear an active alarm or its
  repair issue.
- Switching the MK3 to long frames never sends the panel state "off" (it was already
  marked "don't send to the device").
- On multi-unit systems, the home address is only taken as selected once the MK3 has
  confirmed it, so no command goes to another unit after a lost reply.
