# Victron VE.Bus (MK3) 1.1.3

Fixes from the first diagnostics of a real MultiPlus-II, and better information for
setting changes that fail.

## Fixed

- **Maximum absorption time** showed 480 h on a MultiPlus-II with an 8 h absorption
  time. The Multi reports this setting in minutes; the sensor now converts it and shows
  8 h.
- **Charge characteristic** showed *Unknown* for "Fixed + storage". It is now read as
  *Adaptive*, *Fixed*, *Adaptive + storage* or *Fixed + storage*.

## Changed

- When a setting change fails because the Multi reads back a different value, the
  error now names the Multi's reply to the write (for example *0x88 setting written*)
  and whether it was a RAM-only or a permanent write.
- The **diagnostics download** contains `last_write`: the last setting change, the
  Multi's reply, the value read back and the raw frames of the exchange.

## Known issue

On at least one MultiPlus-II (firmware 556) every RAM-only setting change fails with
*"Setting N reads back … after writing …"*. The cause is being investigated. If you
see this, please attach the diagnostics (with `last_write`) to an issue. Workaround:
store the setting permanently with the guided dialog (*Store permanently*) or with
`set_setting` and `persistent: true`; see
[Changing settings](https://github.com/tubalainen/victron-vebus-hacs/blob/main/docs/controls.md#changing-settings-beta).
